# CONTEXT_SURFACE — the instruction surface of this repository

Phase 0A raw material for the darkprint context-reset audit. This file **enumerates**; the
rows below judge only in the last column. Every file listed here is
recoverable exactly as it stood at the start of this audit via `git show pre-context-reset:<path>`
— the tag was created before any of this audit's work began, on a clean working tree.

**Scope note on the two large blocks below.** The task instructions require one row per file
and explicitly forbid stopping at the seed list, so every file in the two families below is
listed individually rather than summarized as a directory. But `content/**` (blueprints, node
cards, ontology extensions) and `public/cards/**` + `public/bundles/**` are not independently
authored instruction documents — they are the product's structured data and its mechanically
generated build output (`public/bundles/**` and `public/cards/**` are written by
`scripts/generate-bundles.ts` from `content/` at `npm run build`'s `prebuild` step; verified
byte-identical to their `content/` sources via `diff`). Per the task's own rule to skip claim
extraction on product copy while still listing it, these ~234 rows are typed PRODUCT-COPY
(the `content/` originals) or BUILD-ARTIFACT (their generated `public/` copies) and were not
individually claim-mined into CLAIMS_RAW.md — extracting prose claims from 9 near-identical
DOT graphs and 57 near-identical YAML card contracts would not surface new instruction-surface
risk, only multiply the same handful of patterns ~9-57 times. The ~45 hand-authored documents
above them are where this audit's actual density of claims and instructions lives.
