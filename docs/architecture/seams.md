# 8 · Backend contract seams

[← Back to the index](../ARCHITECTURE.md)

Carried over unchanged from Phase 2A's `SEAMS.md`. One row per interaction that will need a
server. IDs are stable and permanent; a retired seam keeps its number. A `TODO(SEAM-xx)`
comment has been added at each seam's primary anchor in the code (see the per-file list at
the end of this document), so the mapping survives outside this document.

Every row's `Auth required` column reflects what the UI *implies*, since no authentication
exists anywhere in the repository. `owner` means the surface renders only for the handle
`lib/data/account.ts:77` seeds; `session` means the interaction needs a signed-in identity
of any kind; `none` means a public read.

Non-HTTP seams (file upload, in-tab parsing, `localStorage`, the MCP transport, CLI) carry
`n/a` in the method column with the real mechanism named.

Naming used below: `BlueprintSummary` is the gallery-tile subset of `Blueprint`
(`lib/types.ts:219`); `Diagnostic[]` is `lib/core/diagnostics.ts:152`; `CardRef` is
`"id@version"`.
