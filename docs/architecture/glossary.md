# 2 · Domain glossary

[← Back to the index](../ARCHITECTURE.md)

Definitions below are summarised from `docs/architecture-wip/ENTITIES.md` (Phase 2A); no
fact here was re-derived from the code independently of that inventory. The full field-level
detail for every entity is in [3 · Concept model](concept-model.md). The table at the end of
this section — the naming inconsistency table — is carried over from `ENTITIES.md` §10
**unchanged**.

| Concept | Definition | Synonyms in UI copy | Synonyms in code | Where it lives | Status |
|---|---|---|---|---|---|
| Blueprint | A graph of automations, described by a DOT topology plus the node cards its nodes pin. The headline unit of the registry, not "the dark factory" (`ENTITIES.md` §1). | "blueprint", "bundle" (as a working copy), "folder" (as a download), "release", "snapshot" | `Bundle` (raw upload), `ResolvedBlueprint` (joined), `BlueprintRecord` (query index), `Blueprint` (view model), `OwnedBundle`, `Release`, `BundleView` | `lib/core/bundle/types.ts`, `content/blueprints/<slug>/` | LIVE |
| Node card | A versioned, reusable unit of work: one agent's spec, ports, tools and prohibitions. Referenced from a DOT node by `id@version`, never embedded in the topology file. | "Cards" (nav), "Node cards" (`/nodes` h1), "Node card" (spec pages) | `NodeCard`, `CardVersionRecord`, `CardRef`, `Port` (one input/output on a card) | `lib/core/card/schema.ts:26`, `content/cards/<id>@<version>.yaml` | LIVE |
| DOT topology | The blueprint's graph: nodes and edges only, no card content. A DOT node's attributes carry a *pointer* at a card (`card="id@version"`), never the card itself. | "blueprint.dot", "the DOT file", "the topology" | `TOPOLOGY_DOT`, `ResolvedBlueprint.dot`, `DotAttrs`, `ResolvedEdge` (one topology edge, joined to its ports) | `lib/core/dot/**`, `content/blueprints/<slug>/blueprint.dot` | LIVE |
| Resolution | The join of a DOT node to its card, producing `ResolvedNode`. Topology outlives a missing card — an unresolved node is still counted, as a third category alongside unattended/staffed. | "resolves" / "unfinished" / "rejected" (the three states shown on `/upload`) | `ResolvedNode`, `ResolvedBlueprint`, `loadBundle` | `lib/core/bundle/types.ts:43`, `lib/core/bundle/resolve.ts` | LIVE |
| Ontology / vocabulary | The shared vocabulary a blueprint and its cards are written against: five closed kinds of term (`phase`, `node-type`, `risk-marker`, `data-type`, `tool`). A curated core merged with an optional local overlay. | "Ontology" (browser, per D-40), "Ontology file (YAML)" (format), "The vocabulary" (`/ontology` rail label — a naming inconsistency, see below) | `Ontology`, `OntologyView`, `OntologyTerm`, `ContentKind = "ontology"` **and** `VocabularyBrowser`/`BundleVocabulary` | `lib/core/ontology/**`, `content/ontology/extensions.yaml` | LIVE |
| Term | One entry in the ontology: a phase, node type, risk marker, data type or tool. Namespaced (e.g. `lupo/pii-handling`) when local; bare when core. | "term" | `OntologyTerm`, `TermDeprecation` (a term's redirect-on-deprecation record) | `lib/core/ontology/types.ts:27` | LIVE |
| Autonomy | A static graph reading of how much of a blueprint runs unattended, expressed only as a class name (`assisted` / `supervised` / `conditional` / `closed-loop`) — never as the underlying 1-4 ordinal. | "Autonomy" | `AutonomyResult`, `AutonomyClass`, `computeAutonomy` | `lib/core/analysis/autonomy.ts` | LIVE |
| Dark factory | A *computed property* of one graph shape — every node unattended **and** all five phases covered — never the site's category or its goal (D-02, D-28). | "dark factory" | `isDarkFactory` (`AutonomyResult` field) | `lib/core/analysis/autonomy.ts:317` | LIVE |
| Static risk exposure | The engine's structural risk reading over a blueprint's declared and inferred risk markers. Never represented as a security audit. | "Static risk exposure" | `SecurityResult`, `MetricKey = "security"`, `computeSecurity` | `lib/core/analysis/security.ts` | LIVE |
| Phase coverage | Which of the five fixed lifecycle phases (`planning`, `implementation`, `testing`, `debugging`, `deployment`) a blueprint's nodes touch. A description of scope, never a score or a to-do list. | "phase coverage" | `PhaseCoverage`, `computePhaseCoverage` | `lib/core/analysis/phase-coverage.ts` | LIVE |
| Metric | One of six scored axes on a blueprint's scorecard (autonomy, efficacy, reliability, transparency, cost/time, security), each carrying a `source` that decides who may write it. | "scorecard", the six axis labels | `Metric`, `MetricSource`, `metricsFor` | `lib/types.ts:41`, `lib/content/view.ts:150-211` | LIVE (autonomy, security) / MOCK (efficacy, reliability, transparency, cost) |
| Digest | The content identity of a card or bundle: a sha256 hash over canonical JSON (card) or over the DOT plus sorted card digests (bundle), excluding authorship metadata. | "digest", "version sha256:…" | `cardDigest`, `bundleDigest` | `lib/core/hash/digest.ts` | LIVE |
| Registry / Archive / Index | Three separate stores the UI keeps apart: the **archive** (`content/`, immutable, read by `lib/content`), the **index** (`lib/data/**`, everything that moves — votes, downloads, ownership), and `Registry` (`lib/core/archive/registry.ts`, the in-memory query layer rebuilt from the archive each process). | "the registry" (whole product), "the archive", "the index", "the library" | `Registry`, `lib/content`, `ContentStore` (unused) | `lib/core/archive/registry.ts`, `lib/content/**`, `lib/data/**` | LIVE (archive, Registry) / MOCK (index) / PLANNED (`ContentStore`) |
| Author | The person credited on a card, blueprint or comment. A string field on the content itself, unchecked against any account. | "author", "handle", "@username", "owner", "builder" | `Author.username` | `lib/types.ts:167`, `lib/data/users.ts` | MOCK |
| Account | The one signed-in identity the fixture can represent — singular, because there is no session. | "you", "your account" | `Account` | `lib/data/account.ts:45` | MOCK |
| Profile | The public page at one handle: pinned items, counted archive facts, seeded preview signals (downloads, stars, watchers, community support, validated). | "profile" | `Profile`, `PinnedRef` (a pinned blueprint or card, at most two) | `lib/data/profiles.ts:33` | MOCK (seeded fields) / LIVE (counted fields) |
| `similar:purpose` | The one evidence marker of the semantic channel (T300): a hit carrying it was retrieved by cosine proximity of the query to the release's embedded purpose text, not by a token match, and such hits only ever form a contiguous tail behind every lexical hit. Value pinned by T300's suite; constants and calibration live beside `SIMILAR_MIN` in `lib/server/search/embed.ts`. | search results, MCP `search` | `Hit.evidence` | `lib/server/search/embed.ts` | LIVE |
| Validated | How many OTHER accounts' blueprints this handle downloaded, ran, and submitted a run report for (SEAM-84) that made it onto that blueprint's own run evidence. Seeded per handle; does not affect any blueprint's `EvidenceLayers`, which still reads "no verified runs" regardless. | "validated" (account panel) | `Profile.validated` | `lib/data/profiles.ts:78` | PLANNED (the run-report pipeline it presupposes, SEAM-84, is undeclared UI) |
| Owned card | An account's node card, public (a document in `content/cards/`) or private (a fixture in `lib/data/cards.ts`), the card-side counterpart to `OwnedBundle`. | "your cards", "Private" pill | `PrivateCard`, `NodeSummary.visibility` | `lib/data/cards.ts` | MOCK (private rows) / LIVE (public rows) |
| Owned bundle | An account's working copy of a blueprint — published or still a draft, public or private, with an optional fork lineage. No separate `Fork` type exists. | "your blueprints", "bundle" | `OwnedBundle`, `Draft`, `Lineage`, `Drift` (vs. the upstream), `BundleFile` (a listed file), `UpstreamMoved` (a pinned card's upstream repin) | `lib/data/bundles.ts:155` | MOCK |
| Save | A private bookmark. Two disjoint implementations exist today for one UI verb: a 5-row fixture (`SAVES`) and a browser-local `localStorage` set — the code states they are different (`lib/data/bundles.ts:551-552`). | "Save", "Saved" (tab) | `Save`, `SAVES`, `FavoriteStar`, `localStorage["darkprint:favorites"]` | `lib/data/bundles.ts:535`, `components/ui/FavoriteStar.tsx` | MOCK |
| Community signals | The mutable, per-blueprint index row: downloads, votes/support, three community-voted metrics, comments. | "community stars", "support", "N public" | `CommunitySignals` | `lib/data/community.ts:42` | MOCK |
| Comment | A note attached to a blueprint or a card. `id` is local to its parent row today, so the real key is `(slug, id)`. | "Community notes" | `Comment` | `lib/types.ts:178` | MOCK |
| Reported cost | The one metric whoever ran a blueprint could someday self-report; the platform never observes a run. Nothing produces one yet. | "Cost / time", "Reported by runners" | `ReportedCost`, `MetricSource = "reported"` | `lib/data/community.ts:30` | PLANNED |
| MCP server | The proposed read-only interface an agent would use to search and fetch from the registry. No server exists; the page is a design proposal. | "MCP" | `lib/mcp.ts` | `app/mcp/page.tsx`, `lib/mcp.ts` | PLANNED |
| Authoring skill | The `skills/darkprint/` Claude Code skill that interviews an author into a blueprint folder. Installs and runs; does not publish or push. | "the skill", "Assisted Design" | `skills/darkprint/**` | `app/skill/page.tsx`, `skills/darkprint/` | LIVE (install) / PLANNED (push to registry) |
| Stored vocabulary | The shape `release.local_vocabulary` holds: `{ text, terms }` — `text` the author's `ontology/extensions.yaml` **byte for byte**, `terms` its parse. `null` is the other legal value. **Not a bare `OntologyTerm[]`**, which both merged readers refuse: T090 serves `text` verbatim at export rather than re-emitting it from the parse (D-90-03), so a release storing terms alone loses the author's comments, key order and formatting. Published as `StoredVocabulary` from `@/lib/server/archive` since T133 and refused at the WRITE, so a shape the readers would reject can no longer be created (D-133-01) | "Ontology extensions", "the vocabulary" | `StoredVocabulary`, `localVocabulary` (column), `vocabulary` (input field) | `{ text, terms }` in T090/T010/T130 fixtures | Backend, LIVE |
