# design-sync notes — DarkPrint

Repo-specific gotchas for syncing this design system to claude.ai/design.
Read this before a re-sync; it is the accumulated cost of the first import.

## What this repo is, for sync purposes

DarkPrint is a **Next.js 16 application**, not a published component library.
There is no Storybook, no story files, and no built `dist/` of UI. The design
system is 182 components under `components/**/*.tsx` plus a Tailwind v4
`@theme` block in `app/globals.css`. That means `shape: "package"` running in
the converter's **synth-entry mode** (no dist entry, no shipped `.d.ts`).

Everything the sync needs that the repo does not already build is generated by
`node .design-sync/prepare.mjs` (wired as `cfg.buildCmd`), which runs three
steps in order: content snapshot, CSS compile, types + staging package.

**The build needs an explicit `--entry`**, and the path must go through the
package link so the converter's walk-up stops at the staging `package.json`:

    node .design-sync/prepare.mjs
    node .ds-sync/package-build.mjs --config .design-sync/config.json \
      --node-modules ./node_modules --entry ./node_modules/darkprint/entry.mjs \
      --out ./ds-bundle
    node .ds-sync/package-validate.mjs ./ds-bundle

Passing `.design-sync/.cache/pkg/entry.mjs` directly does NOT work: the walk-up
finds the repo's own `package.json` first and `PKG_DIR` becomes the repo root,
which silently loses `cssEntry` and the types tree.

## The staging package (`.design-sync/.cache/pkg`)

`node_modules/darkprint` is a **symlink to `.design-sync/.cache/pkg`**, not to
the repo root. Recreate it after any `npm install` that removes it:

    ln -sfn ../.design-sync/.cache/pkg node_modules/darkprint

Why it exists, since a plain self-link to the repo root is the obvious move:

* The converter resolves `PKG_DIR` as `join(NODE_MODULES, cfg.pkg)` unless
  `--entry` is passed — and passing `--entry` disables source discovery
  entirely (the `deriveComponentsFromSrc` fallback only runs in synth-entry
  mode), so a link of some kind is required.
* It finds the prop-extraction entry through `package.json` "types". This app
  has no reason to declare one, and the generated tree cannot live in the repo
  root: `tsconfig.json`'s include is `**/*.ts`, so a root `types/` and
  `index.d.ts` would be pulled into the app's own `npm run typecheck`.

The package is assembled by `scripts/gen-types.mjs`: a `package.json` naming
the types entry, the emitted `types/` tree, a copy of the compiled stylesheet,
and symlinks for `components`, `lib`, `docs` and `.design-sync`.

**Every `cfg.*` path field resolves against `PKG_DIR`**, which is why
`.design-sync` has to be reachable from inside the staging package — that is
how `cfg.tsconfig` and `cfg.extraFonts` are found. `lib` is linked because
`cfg.tsconfig`'s own `baseUrl` is interpreted relative to wherever the config
is read from, so `@/*` resolves against the package root.

## Two components share a name with two others

`BlueprintGraph` and `WatchButton` are each **declared in two different files**:

| name | shipped | shadowed |
| --- | --- | --- |
| `BlueprintGraph` | `components/graph/BlueprintGraph.tsx` | the inline SVG in `components/explain/RunLayers.tsx` |
| `WatchButton` | `components/bundle/WatchButton.tsx` | the variant in `components/profile/SocialControls.tsx` |

The design-system namespace is flat, so one name can only carry one component.
The converter's synthesized entry is `export * from` every file, and ESM drops
a name two modules both export — both came out **undefined** on
`window.DarkPrint` while still being listed in the manifest, which the render
check does not catch because the preview falls back to the floor card.

`scripts/gen-types.mjs` therefore emits an explicit `entry.mjs` (one
`export { Name } from ...` per component, same list as the types barrel), and
that is what `--entry` points at. In each case the winner is the file named
after the component; the shadowed one is a private helper inside a larger file.
**If a third same-named component appears, it is silently shadowed** — the
generator picks the file-named one and nothing warns.

## Prop contracts: the single biggest quality lever

With no `.d.ts` tree the extractor produced `[key: string]: unknown` for **all
182 components** — an empty contract for the design agent to code against.
`scripts/gen-types.mjs` runs `tsc --emitDeclarationOnly` over
`components/**` + `lib/**` into the staging package, and an explicit
re-export barrel (`types/index.d.ts`) gives the extractor its entry.

Result: 157 components get real prop types with JSDoc preserved
(`variant?: "primary" | "outline" | "ghost"`), and the remaining 25 are
genuinely zero-prop components pinned via `cfg.dtsPropsFor` to say so rather
than claim they accept anything.

* The barrel is **one explicit `export { Name } from ...` per component**, not
  `export *`: `WatchButton` and `BlueprintGraph` are each declared in two
  different files, and ESM drops names two modules share as ambiguous.
* `tsc` exits non-zero on `lib/db/*`'s `.ts`-extension imports even though
  they are excluded from the program's roots, so `gen-types.mjs` judges the
  emit by whether `types/components/` appeared, not by exit code.
* Types crossing into `@/lib/*` degrade to `any` — the ts-morph project the
  converter builds has no `paths` configured and cannot resolve the alias.
  Primitive and enum props, which are most of the value, are exact.

## Next.js runtime shims

Components import `next/link` (44×), `next/navigation` (6×) and `next/image`.
Those read the App Router context, which no rendered design has. They are
aliased to browser stand-ins in `.design-sync/shims/` through
`.design-sync/tsconfig.sync.json`. `next/headers` never appears in a `.tsx`.

**Key ordering in `tsconfig.sync.json` is load-bearing.** The resolver walks
`paths` in key order and accepts the first hit, testing the bare stem before
any `/index` candidate — so a bare stem that is a *directory* wins. Every
directory-style specifier must therefore sit **above** the `@/*` wildcard.
Currently pinned: `@/components/viz`, `@/lib/content`, `@/lib/core`.

`@/lib/server/*` is deliberately **not** mapped. Those four imports are
`import type` only and are erased before resolution; leaving them unmapped
means a future value import fails loudly instead of quietly pulling Postgres
into a browser bundle.

## The content snapshot

`lib/content/index.ts` says SERVER ONLY in its own header — it reads
`content/` off disk at module scope. Four components call into it
(`SectionNodeCard`, `SectionNodeIsCard`, `SectionBlueprint`, `ScoringModel`)
and **every call site passes a compile-time constant**, so the reachable data
is a fixed, tiny set. `scripts/snapshot-content.mjs` runs the real loader
under Node and emits it as a browser module, which is why those cards show the
actual archive instead of empty state.

**Re-run it whenever `content/` changes** — the snapshot is the archive frozen
at build time. If a component starts asking for a different card or bundle,
add that call to the entry inside the script or it will silently get the
fallback.

## Styling and fonts

* `app/globals.css` is a *source* file: it carries the `@theme` tokens but no
  utilities, which Tailwind generates by scanning markup. `build-css.mjs`
  compiles `.design-sync/css/entry.css` (globals + xyflow + `@source` globs)
  to ~146 KB. The `@source` list includes `.design-sync/previews/**`, so a
  class used only in an authored preview still lands in the stylesheet —
  **authoring a preview requires re-running prepare before the build.**
* The card template closes its `<head>` with `body{background:#fff}`, which
  lands after the stylesheet. Against globals.css's near-white `--color-fg`
  that renders every card white-on-white. `entry.css` ends with an `html body`
  rule that outranks it on specificity rather than order.
* Fonts are Geist, JetBrains Mono and Space Grotesk, loaded in the app by
  `next/font`, which exists only at runtime in Next. `.design-sync/fonts/`
  carries the woff2 files and a hand-assembled `@font-face` sheet that also
  binds `--font-geist-sans`, `--font-jetbrains-mono` and
  `--font-space-grotesk` — nothing sets those variables outside the app.

## Grouping

`.design-sync/overrides/source-kit.mjs` forks the discovery adapter for two
reasons, both declared in `cfg.libOverrides`:

1. `ui` is in the converter's `GENERIC_DIR` set, so all 38 primitives fell
   into a single `general` bucket. Here `ui` is a real group.
2. A group directory may share its component's name (`hero/Hero.tsx`), and the
   filter that drops a segment repeating the component name left `Hero`
   groupless. It now falls back to the last non-generic segment.

`cfg.componentSrcMap` pins all 182 source paths, regenerated by
`scripts/gen-src-map.mjs`. Without it the converter finds a component by
filename only, which misses every secondary export — this repo puts several
components in one file (`Badge.tsx` also exports `KindBadge`,
`PartFigures.tsx` exports six figures) and an unmatched component loses both
its group and its JSDoc. **Re-run `gen-src-map.mjs` after adding or moving a
component.** Hand pins go in `cfg.componentSrcMapPins`, which is merged over
the generated map and survives regeneration; `cfg.dtsPropsForPins` works the
same way for prop bodies.

The generator skips ALL-CAPS names (`NAV`, `LAYERS`, `COLS`) — they are
constants, and the converter drops them on its own, so a non-null map entry
would re-add them as components.

## Known render warns

Checked against on re-sync; a warn NOT in this list is new and wants looking at.

* `[RENDER_THIN] RubricGlyph — mounts have no text and paint nothing`.
  Legitimate. It is a pure SVG figure (three criterion rules, each with a
  four-step scale) drawn in `currentColor` with no text by design. The
  screenshot was confirmed: it renders correctly in both authored cells.

## Non-ASCII in the bundle

esbuild escapes non-ASCII in string literals but **not inside regex literals**,
so a regex written with raw glyphs makes the whole bundle depend on being
decoded as UTF-8. Three were found and fixed at source on 2026-08-26
(`BundleDropzone.tsx`, `DotBreakdown.tsx`, `lib/format.ts`); the combining-marks
class in `BundleDropzone` threw `SyntaxError` and took the entire bundle down,
leaving all 182 components undefined on the global.

**Write regex literals with `\uXXXX` escapes.** The ~640 non-ASCII bytes left
in the bundle are all inside JSDoc comments, which are harmless. If
`[BUNDLE_EXPORT]` ever reports a large number of components "not a component on
window.DarkPrint", check for a new raw glyph in a regex before anything else.

## Authoring previews: traps this repo actually sprang

Folded from six parallel authoring agents. Every one of these cost somebody a
debugging cycle.

### The preview stylesheet is only as fresh as the last `prepare.mjs`

`.design-sync/css/entry.css` **does** carry `@source "../previews/**/*.tsx"`, so a
Tailwind class used only in a preview compiles fine. But `preview-rebuild.mjs`
does not rebuild the CSS, so a class written since the last `prepare.mjs` run is
absent from the sheet and silently does nothing: no error, no warning, the
element just misses the rule. Two agents independently lost time to this and
concluded previews are never scanned, which is not true.

**Run `node .design-sync/prepare.mjs` before judging a preview's styling.**
Fixed-size utilities (`h-72`, `min-h-[360px]`) are the shape most likely to be a
preview-only invention, so they are where it bites first.

### `preview-rebuild.mjs` transpiles, it does not typecheck

esbuild strips types without checking them, so a wrong prop shape compiles clean
and fails silently at runtime. The example that cost the most: `FlowEdge` and
`FlowAbsence` take `from`/`to` as `readonly [number, number]` tuples, and passing
`{x, y}` makes every downstream `from[0]` undefined, so the path resolves to
`"M NaN NaN"`. The edge is in the DOM, fully styled, and completely invisible,
with nothing on the console. A screenshot of that reads as a layout choice rather
than a bug. When something is missing from a card and there is no error, read the
computed attribute in a browser before assuming the composition is wrong.

### A preview must not import a bundled third-party library directly

`preview-rebuild.mjs` compiles each preview as its own bundle, so importing
`@xyflow/react` in a preview creates a second copy with its own React context
identity. `AgentNode`'s `<Handle>` then throws "Seems like you have not used
ReactFlowProvider as an ancestor" even with a provider plainly in the JSX tree.
Reach for the real exported parent from `darkprint` instead (`BlueprintGraph`),
which keeps node and provider in the one compiled copy.

### Previews can call the real engine, and should

`cfg.tsconfig` maps `@/lib/core` to the real isomorphic core and `@/lib/content`
to the browser snapshot, so a preview can resolve the real archive bundle and
call `resolveBundle`, `analyzeBlueprint`, `graphForBlueprint`, `ontologyView`,
`buildPaneModel` rather than hand-typing an `AutonomyResult` or a `PaneModel`.
Every number on those cards is then what the engine computes. Type-only imports
from anywhere under `@/` are free at runtime, since esbuild elides them without
resolving the module. A **value** import from `@/lib/server` is not, and must
stay out.

### Fixtures are read by more of the tree than you expect

`ContentCard` reads `analysis.autonomy.contributions`; `ContentRow` also reads
`analysis.phaseCoverage.covered`/`.missing` for its `CoverageStrip`. A fixture
built for the first blanks the second with no visible error.

### Components with no visible form under the harness

Four needed harness-level answers rather than better composition. The pattern is
the same each time: give the component the environment it reads, then let its own
code run.

* **A route.** `LearnShell` picks its rail off `usePathname()`. The navigation
  shim reads `window.__dsPathname`, so a preview sets that at module scope.
* **A session.** `HeroAction` gates all four states on `GET /api/auth/session`,
  and only a 401 reaches the anonymous branch. Its preview answers that one
  request and passes every other through.
* **Reduced motion.** `useScrollProgress` starts at the finished state and steps
  back to animate only when `useMotionAllowed()` allows it. The capture harness
  never emulates `prefers-reduced-motion`, so scroll-choreographed components
  (`CardWalk`, `SourceSwap`) freeze at their entrance frame and hide the content
  they exist to reveal. Their previews stub `matchMedia` for that one query.
* **Width.** `SideRail`'s aside is `hidden xl:block`, so below 1280px it has no
  appearance at all. `SideRail` and `LearnShell` carry a `1400x900` viewport.

`RailScrollSpy` is a fifth shape: it renders `null` and only writes an attribute
onto a `SideRail` row via a scroll listener. Its preview reproduces the row
markup and sets the active state directly, with hrefs pointing at fragments that
do not exist on the isolated page so the real effect cannot overwrite it.

### `cfg.overrides` carries the card geometry

Sixteen components need it. `cardMode: "column"` gives one export per row at full
card width; `viewport` raises the render frame for a composition that is
legitimately tall. A component cut off mid-composition is a geometry problem, not
a reason to shrink the fixture: trimming `AccountForm` to fit would have
misrepresented what a seven-section settings form is. Changing a `viewport`
requires a full `package-build.mjs`, not a targeted `preview-rebuild.mjs`, which
reports `[CONFIG_STALE]`.

One authoring trap in the same family: `ChoiceGraphPane`'s listbox is
`max-h-[15rem] overflow-auto`, so a six-node fixture pushes its "Not drawn" group
past the scroll boundary. A static capture cannot scroll. Keep graph fixtures
small enough that every group fits.

## Re-sync risks

* **`node_modules/darkprint` is not created by `npm install`.** A fresh clone
  or a reinstall leaves the converter unable to find the package. Recreate the
  symlink (command above) before running anything.
* **The content snapshot is frozen data.** It is regenerated by `prepare.mjs`,
  but if a component starts reading a card or bundle the snapshot entry does
  not name, it silently falls back to empty rather than failing.
* **Preview CSS is scan-dependent.** Classes only appear in the stylesheet if
  `prepare.mjs` runs *after* the previews are authored. Authoring a preview and
  going straight to `package-build.mjs` yields an unstyled card.
* **The `source-kit.mjs` fork should be diffed against the bundled
  `lib/source-kit.mjs`** on re-sync and merged if upstream moved.
* **`.d.ts` emit depends on the repo typechecking.** If `npm run typecheck`
  starts failing, declaration emit may drop components and their contracts
  silently degrade to `[key: string]: unknown`. Compare the contentless count
  against 25.
* **`eslint.config.mjs` ignores the three generated trees** (`ds-bundle/`,
  `.ds-sync/`, `.design-sync/.cache/`). Without those globs the repo's own lint
  gate reports ~396 errors against generated declarations. The hand-written half
  of `.design-sync/` is deliberately still linted, and does lint clean.
* **The emitted `.d.ts` sit inside the app's `tsconfig` include** (`**/*.ts`
  reaches `.design-sync/.cache/`). They typecheck clean today; if a future emit
  produces something `tsc` rejects, `npm run typecheck` will fail in generated
  files rather than in anybody's source.
* **`.design-sync/previews/**` is linted on purpose** (only `.cache/` is ignored),
  so a preview is subject to the repo's own rules. `react/no-unescaped-entities`
  is severity 2 here: an apostrophe in JSX text must be `&apos;`. Two authored
  previews tripped it. Run `npm run lint` after an authoring wave.
* **Three previews carry harness stubs** in their own module scope, and each
  exists because the component reads something the capture environment does not
  provide: `HeroAction` answers its own session fetch with a 401, `CardWalk` and
  `SourceSwap` answer `prefers-reduced-motion` as `reduce`, and `LearnShell`
  sets `window.__dsPathname`. If a future component needs the same, copy the
  pattern rather than weakening the component.
* Verified against commit 27183d6 on 2026-08-26, Node 26.7.0, TypeScript 5.9.3,
  Tailwind 4.3.3, Playwright chromium-headless-shell 151.
